# Windvale kernel native implementation seam

## Status and purpose

Kernel native seam version 17, WVA seam version 8, admission bridge version 2, retained bridge 10, and paging version 4 compose qualified Probe 32 with interpreter profile 6, memory 9, and protected processes 11. Resource records remain version 4 and the OS-private directory remains `WVBR002`. [Decision 0103](../Documents/Decisions/0103-Second-Exact-Wvb-And-Broader-Scalar-Control-Flow.md) owns the composition; [Decisions 0099](../Documents/Decisions/0099-Bounded-Native-Frame-Admission.md) and [0101](../Documents/Decisions/0101-First-Exact-Wvb-Across-Three-Environments.md) retain its qualified ABI and OS history. WVA seam version 9 and exception version 3 are the current locally verified candidate: they move the common terminal handler and serial loop from raw C# emission into canonical WVA/WVO without changing the normalized trap contract. Cross-host and pinned-QEMU requalification remain pending.

This contract prevents temporary C# machine-code generation from silently becoming the kernel architecture. It also avoids pretending that privileged x86-64 entry mechanics belong in ordinary source code.

## Implementation roles

| Layer | Current responsibility | Direction |
| --- | --- | --- |
| C# reference/recovery host | Compile WVB, select and verify current ABI-17 native code, adapt external object symbols, assemble, link, package PE32+, provide host oracles, and retain bounded loader, memory/release, exception-descriptor, paging/process construction, descriptor/MSR, dispatcher, and bridge emitters while replacements are unavailable. | Remains an independent recovery and comparison path; does not define kernel, WVB-admission, terminal mechanics, or process policy. |
| Shared portable-WVB backend | Lower verified portable semantics into the same versioned native ABI and WVO object used by host JIT/AOT evidence. | Replaces special OS instruction selection incrementally and becomes Windvale-written. |
| WVA machine layer | Own explicit entry/exit and capability-adapter shims, register-frame mechanics, and later named privileged instructions that ordinary Windvale code must not execute ambiently. | Grows only from concrete kernel requirements with exact encodings and verification rules. |
| `.wv` system layer | Own kernel policy, state transitions, diagnostics, allocation decisions, exception dispatch, and later runtime services once the shared native target can lower them. | Becomes the primary kernel implementation. |

New kernel mechanisms should default to WVA for irreducible machine mechanics and `.wv` for policy. Additional raw C# instruction emission requires a documented compiler or assembler blocker and a named replacement seam.

The retained native probe bridge then:

1. reserves 120 aligned stack bytes and preserves the copied-handoff pointer from `RCX`;
2. constructs the exact 112-byte execution context with version/size, WVB instruction budget 271, call-depth budget 2, zero service-table, record-arena, text-arena, service-failure-detail, argument-table/count, output-table, file-input-table, file-output-table, and reserved fields;
3. passes the context pointer in `RDX` and calls the ABI-17 portable export `Main`;
4. accepts only the complete packed result `RAX == 29`;
5. returns failure 1 on a trap, exhausted budget, or wrong result; and
6. restores `RCX` and tail-transfers to special compiler export `Windvale_kernel_main` on success.

The compiler object imports `Windvale_kernel_write_byte`, which resolves to the WVA export. WVA tail-transfers each call to explicitly internal symbol `Windvale_kernel_x64_write_byte`. The public kernel capability boundary is therefore WVA-owned even though its current COM1 instruction sequence remains bootstrap code.

The builder independently decodes the assembled WVA objects, paging/process objects, both bridge objects, and all portable native objects and requires their exact architecture, section, symbol, code, and relocation shapes before linking. On normal Probe 32, final success requires exact WVB admission, Windvale set selection, atomic typed grant, two resource reads, budgeted four-function scalar/control-flow interpretation in both client generations, send/exit, two-alias cleanup, retained native probe, and Main. Kernel-fault paths retain terminal WVA normalization; the user-fault path contains vector 13 and performs the same cleanup.

## Portable native probe

`Operating-System/Kernel/Native-Wvb-Probe.wv` is an ordinary portable module, not system-profile source. It owns immutable i32 array `[3, 5, 8, 13]`, immutable byte header `[0, 5, 0, 0, 0, 255]`, a two-parameter `Add`, borrowed-byte `Readˉheader`, one bounded loop, and exported `Main() -> i32`. It passes bytes through an internal function, slices a four-byte payload, performs checked `u8` and little-endian `u32` reads, and validates the values before accepting the sum. The reference interpreter requires exactly 271 WVB instructions and active call depth 2 to return 29. The shared native object has separate code and read-only data plus four verified RIP-relative relocations.

The retained native probe is compiled and AOT-linked on the host; its WVB is not interpreted in the guest. Separately, Probe 32 validates the exact 815-byte canonical `Sourceˉwvbˉfixture` WVB, grants it with the four-byte budget twice, executes 199 guest opcodes across four functions and four scalar families in each interpreter generation, and removes both terminal alias sets. Each interpreter context supplies a 1,024-byte record arena inside its existing RW/NX data page and must report exactly 528 bytes used; init and the retained native probe need no arena. The largest generated interpreter frame is 1,900 slots, so ABI 17's 2,048-slot compiler limit remains unchanged. Verified call-graph preflight derives 58,800 exact stack bytes and the minimal 15-page envelope. Reaching the retained resource/runtime markers proves the two OS results `6`; `native-wvb=pass` still owns the later retained AOT computation to `29`. None claims a general loader, capability-transfer facility, general allocator, or JIT.

## Native compiler requirements for policy migration

ABI 17 retains ABI 16's portable service semantics and 64-parameter internal call convention while raising the verified frame envelope to 2,048 cells. The retained kernel portable-probe bridge still passes zero service-table, record/text-arena, argument, output, file-input, and file-output fields because that module uses none of those facilities; the separate user interpreter context supplies the bounded record arena described above. Moving the raw allocator/release emitter and future exception policy into ordinary `.wv` still requires:

- `u64` values and checked address arithmetic;
- explicit unsafe or system-visible bounded memory loads and stores;
- a specified kernel ABI for scalars, state pointers, return values, nonvolatile registers, and trap dispatch; and
- imports of narrow WVA services without granting ambient privileged instructions.

These are requirements on the native target, not permission to change source semantics implicitly. Each migrated kernel policy function must retain a C# oracle or differential test until independent native evidence is sufficient.

## Safety and migration limits

WVA remains semantically checked assembly. Executable version 8 adds only the three process-normalization exports while retaining paging, `push_i32`, and shutdown mechanics. The version-9 candidate adds the terminal export, local serial function, and marker data. The WVA grammar also includes the exact no-operand `syscall` statement used by the separate user shims. The later WVA 1 expansions add typed 8/16/32/64-bit register, immediate, shift, RIP-relative, and indexed-memory operations plus condition materialization, extension, and byte port I/O without adding arbitrary executable-byte directives or generic MSR/control-register access. The current native-probe bridge, admission bridge, memory tail-release emitter, and process machine remain because their blockers now center on broader implicit-register mechanics, checked state policy, ABI-specific sequences, and migration evidence rather than byte/word access alone. Every seam has exact independently decoded shape and a named future replacement owner.

The seam does not move the UEFI loader, memory-map scanner, arena initializer, allocator/release machine implementation, page-table/process-root constructor, descriptor/MSR publication, syscall dispatcher, external-symbol adaptation, PE32+ packaging, or native compiler out of C#. The raw objects establish verified link positions through which those pieces can be replaced without changing the loader-to-source evidence chain. WVB admission and process generation/lifecycle policy are Windvale-owned. Q35 poweroff, normalized trap-entry sequences, terminal COM1 mechanics, user syscall bytes, NX/WP activation, and CR3 activation are WVA-authored; Stage 0 only assembles, validates, links, and packages them.

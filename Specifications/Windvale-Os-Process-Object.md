# Windvale OS process-object build

## Status and purpose

This contract defines ordinary Windvale-native construction of the normal
Probe 40 `05-process.wvo`. The object contains one reviewed x86-64 process-code
fixture plus embedded images and records regenerated from canonical Windvale
sources. It does not define another compiler, linker, WVO format, or process
semantic implementation.

## Public commands

```bat
Tools\Native\Build-Os-Process-Object.cmd output.wvo
```

```sh
./Tools/Native/Build-Os-Process-Object.sh output.wvo
```

The destination must use `.wvo`, must not exist, and must have an existing
parent directory. The builder validates the host-specific toolset and fixture,
uses a unique private sibling directory, and publishes only an independently
admitted final WVO. Failure must preserve an existing destination and remove
private work.

## Construction chain

The builder performs these bounded steps:

1. Build the canonical init/resource, directory, filesystem, and network
   services, bytecode interpreter, and `Function-Only.wv` program to exact WVB
   identities.
2. Lower the five executable modules through the accepted-subset native lowerer,
   then rename their `Main` exports to the established link-facing symbols.
3. Assemble the init, directory, filesystem, network, boot-resource, and normal
   client WVA shims.
4. Turn the admitted boot-resource stencil into its final object and link the
   exact init, directory, filesystem, network, and client images at base address
   zero.
5. Construct the canonical `WVRS 1` resource store and `WVDS 1` directory
   snapshot from their Windvale-owned encoders.
6. Check the retained 68-byte syscall dispatch window, preserve operations 1
   through 7 byte-for-byte, redirect only its former failure jump through a
   9-byte operation-8 extension, append the 183-byte handler in the same
   canonical code section, and bind it to the separately assembled
   current-context and user-copy leaves.
7. Combine those generated bytes with the pinned 46,678-byte
   `normal-x64-process.bin` architecture fixture through the Windvale-owned WVO
   layout and relocation encoders.
8. Require the 951,843-byte identity
   `2ea81c1e4e5bbeb2656dd3a938b330f391fd3749b54a6b4f5cafde45af1e74b2`,
   independently verify the WVO, and publish it through the native publisher.

The nine embedded data payloads total 901,759 bytes and are always regenerated.
The filesystem and network images are boot-linked but are not yet launched by
the Probe 40 architecture fixture; their checked service profiles remain the
admission boundary for the next launch integration step.
Only the retained `.text.process` input remains a reviewed architecture
fixture. The ordinary producer checks its former dispatch bytes before
installing operation 8; malformed or drifted input is rejected. Its exact 21,918
step and depth-5 native policy context is sufficient for the composed
ResourceDomain1, two-generation versioned start/executable-publication, and machine-construction admission
paths while retaining the kernel stack and all other process bytes, at SHA-256
`112dd0cb06de269e069436720876829313fb0a20546d1d7b38ea336fea26e6fd`.
The one-time Windvale code extractor validates the predecessor WVO shape before
copying that exact section; it is provenance tooling and is not part of the
ordinary build.

## Toolset and source organization

`Artifacts/Native-Os-Process-Object-Toolset-Candidate` binds paired Windows and
Linux applications for boot-resource publication, resource-store encoding,
directory-snapshot encoding, and final WVO construction. Their portable sources
remain separated by ownership: object layout, application-start patch,
relocation records, hosted CLI,
resource store, snapshot, and boot-resource transformation are focused files.
This avoids reintroducing the former monolithic managed process constructor as
one oversized Windvale source.

## Focused evidence

`Test-Os-Process-Object` owns exact reconstruction, independent WVO admission,
existing-output preservation, and private-work cleanup. The existing compiler,
lowerer, assembler, linker, publisher, and malformed-input suites retain their
own lower-level contracts. Cross-host execution belongs to the final grouped
retirement gate.

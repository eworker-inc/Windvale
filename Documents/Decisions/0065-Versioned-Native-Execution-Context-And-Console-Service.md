# Decision 0065: Versioned native execution context and console service

- Date: 2026-07-31
- Status: Implemented; exact cross-host qualification pending
- Refines: [Decision 0063](0063-Shared-Budget-Native-Calls-And-Static-Data.md)'s positional ABI-5 resource bridge
- Updates: [Decision 0064](0064-First-Shared-Native-Wvb-In-Windvale-Os.md)'s OS consumer to the current ABI without changing its portable program

## Context

ABI 5 proved shared instruction/depth budgets, calls, loops, and immutable i32 data, but its six positional entry arguments were a temporary cross-platform trick rather than an extensible runtime boundary. A useful native Windvale tool needs explicit authorized host services without embedding Windows or Linux calls in generated code, while Windvale OS must keep consuming the same generated ABI for capability-free AOT modules.

The first service should remain small enough to verify completely. `console.write_line` already exists in source, WVB, the reference runtime, and the Windvale-written compiler. Static module text avoids allocation and general value-layout decisions while still proving UTF-8 data, authorization, a service table, a real external callback, error containment, and identical generated bytes on both hosts.

## Decision

- Advance the experimental target to `x86-64-wvb-baseline-v6` and native ABI version 6. Do not accept ABI-5 fragments through a compatibility branch; their qualified artifacts remain historical evidence.
- Replace positional entry budgets with a pointer in `RDX` to the exact 32-byte version-1 [native execution context](../../Specifications/Windvale-Native-Execution-Context.md). It carries format/size, 64-bit instruction and depth budgets, and an optional service-table pointer. `Main` preserves `R15`, retains the context there, and restores it on every success and trap path.
- Add the exact 16-byte version-1 service table. Its first and only entry is `console.write_line`. A fragment's required-service metadata is canonical and closed: empty or exactly that service.
- Admit hosted native compilation only for a module declaring exactly `console.write_line(text) -> void`, with no nominal types and only immutable i32-array or text data. Lower text to strict UTF-8 `.rodata`. Admit static-text locals only when every use is proven to retain one identical immutable data identity; reject dynamic or ambiguous text.
- Keep generated fragments identical on Windows and Linux. Generated code passes the text address/length in `R8`/`R9D` and calls the table entry. Runtime-owned exact thunks translate only that call to Windows `RCX`/`EDX` or System V `RDI`/`ESI`, preserve the shared counters/context register, and contain callback failure as packed status 5 / `WVR3013`.
- Require explicit capability authorization before executable allocation (`WVR3010`) and an implemented output service (`WVR3001`). Revalidate the complete text range against the verified fragment, enforce the UTF-8 byte bound, decode strictly, and append LF.
- Extend the independent fragment decoder over the exact context prologue, service call, relocation, UTF-8 target/length, failure edge, packed service status, and `R15` restoration. Corrupt service code, patch bytes, metadata, or UTF-8 must fail before WVO or W^X publication.
- Preserve required-service metadata in the verified native fragment. Do not claim standalone hosted AOT loading from WVO 1.0, because that object format does not yet serialize the service requirement. Linked service code executes only while paired with its original verified fragment contract.
- Advance the OS native bridge to version 2. Construct the same ABI-6 context on the kernel-owned stack with exact budgets 203/2 and a zero service pointer; reject any required service in the portable probe. Advance the firmware probe to version 8 and add `native-context=pass` to its gated transcript.
- Retain C#/.NET as the current host adapter, selector/verifier implementation, reference oracle, and recovery path. The qualified Windvale-written bytecode compiler remains real Stage 1/Stage 2 code, but it does not yet own native selection, W^X publication, allocation, or platform services.

## Initial evidence

The focused Windows service case compiles the canonical hosted Hello module twice, verifies deterministic fragments and WVO, retains immutable UTF-8 `.rodata`, links back to the exact fragment bytes, and produces `Hello from Windvale` plus LF through the actual W^X machine-code callback. Interpreter and native execution agree at the exact instruction boundary. Missing authorization, missing implementation, and deliberate writer failure produce `WVR3010`, `WVR3001`, and `WVR3013`; corrupt service bytes, relocation bytes, service metadata, and UTF-8 data fail before execution.

The ABI-6 portable regression, all 49 regular Seed tests, and all 15 OS tests pass with a zero-warning Release build. The unchanged 502-byte portable OS WVB lowers to a 2,360-byte ABI-6 WVO with SHA-256 `712350a395120c42f604966dffe04c397012af3696666f51c1a069cd9db0be61`. The exact version-2 bridge object is 305 bytes with SHA-256 `2e22ee17e52ee8cc2c8fa6547424f0234bd770555b0a75c23d63003b6257331e`. The development firmware image is 10,240 bytes with SHA-256 `61cd90eac963ed96d1fdd86d447cb7f2cdeffa50a3de2f5306239de27c1be6b0`. A real pinned QEMU 11/OVMF boot emits the complete version-8 transcript including `native-context=pass` and returns the guest-controlled success code.

These values are implementation evidence, not qualification claims. The exact committed candidate must still pass the complete Windows and isolated Debian suites, native Linux callback execution, portable-artifact comparison, and an exact-candidate QEMU rerun before this decision becomes qualified.

## Consequences

Windvale now has the first real versioned native runtime boundary rather than another positional bridge argument. One hosted source capability crosses WVB, native IR, identical generated x86-64, WVO/AOT and W^X paths, explicit authorization, platform adaptation, and deterministic output. Capability-free OS AOT code consumes the same context shape.

This is not a general native runtime or a native compiler. There is no dynamic text, bytes value representation, allocation, file/process service table, PE/ELF hosted container, standalone service metadata in WVO, Windvale-written thunk/runtime, or .NET-free tool execution. The next useful tool pressure is bounded bytes plus narrow file/argument services, followed by enough aggregate and allocation support to move an existing Windvale-written inspector or compiler component through the native path.

## Reconsider when

- A second service requires table growth, returned values, owned buffers, cancellation, or asynchronous completion.
- The first standalone hosted AOT container must preserve capability requirements independently of `Nativeˉfragment`.
- Dynamic text/bytes or aggregates require a native value representation and allocation/root contract.
- The Windvale-written native selector, fragment verifier, or host runtime begins replacing its C# Stage 0 counterpart.

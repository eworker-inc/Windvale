# Decision 0151: Native descriptor allocator emission schedule

- Date: 2026-08-03
- Status: Implemented and cross-host qualified
- Retains: Native ABI 22, execution-context version 7, service-table version 5, target `x86-64-wvb-baseline-v22`, WVB 1.6, WVO 1.0, every selected ABI-22 byte, and all host/OS consumers
- Plans: Candidate execution-context version 8 with an append-only 128-byte layout
- Refines: [Decision 0147](0147-Native-Descriptor-Ownership-Plan.md) and [Decision 0148](0148-First-Wva-Native-Descriptor-Allocator-Leaf.md)

## Context

Decision 0147 identifies every semantic ownership action, and Decision 0148 supplies the executable WVA allocator leaf. Decision 0150 advances ABI 22 through a narrower generation-owned buffer and checkpoint policy without calling that leaf. A later full allocator integration still cannot safely join the semantic plan and leaf without another explicit boundary. The semantic plan does not state where an owner token physically resides, whether an action occurs before replacement or after definition, which acquisitions belong inside runtime services, or where a function can place the allocator's 40-byte request.

The integration also has a hidden register constraint. Generated code keeps its instruction and call-depth budgets live in `R11` and `R10`, while the platform-neutral allocator leaf correctly treats both as volatile. Inserting calls without a preservation contract would silently corrupt those budgets even when allocation itself succeeds.

## Decision

- Attach one immutable format-1 descriptor-allocator emission plan to native machine IR after the format-1 ownership plan and direct-record storage offsets are verified. Require the shared ABI-22 selector to verify this plan even though it does not emit the WVA leaf yet.
- Reconstruct every function summary and ordered emission through a separately implemented verifier. Changed phases, locations, counts, frame bounds, context fields, or emission order fail as `WVN2905` before instruction selection.
- Plan candidate execution-context version 8 as an append-only extension of version 7. Retain all existing offsets through byte 111, place the allocator-state pointer at offset 112, place the WVA leaf pointer at offset 120, and set the total size to 128 bytes. This plan does not publish a version-8 context yet.
- Treat descriptor byte offset 12, the pre-ABI-22 reserved word now used for generated ownership generations, as the candidate full-allocator owner-token location. Preserve pointer and length at offsets 0 and 8. A later ABI must choose one meaning for that high word; it must not mix generation and allocator tokens.
- Publish two physical owner-addressing forms. A direct-frame location names an absolute 16-byte frame cell plus owner displacement 12. An indirect-record location names a frame cell containing a borrowed record handle plus `field * 16 + 12`. The second form prevents copied assumptions about caller-owned record-parameter storage.
- Classify allocator work into five phases: function entry after argument setup, before an operation for retain-before-release replacement, within an allocating operation, after an operation for definition ownership and last-use release, and terminator cleanup.
- Preserve the ordered semantic actions. Assignment retains the incoming backing and releases the previous target before the descriptor copy. Aliases and copied values retain after the result exists. Last-use release follows the operation. Return cleanup releases owned locals and direct-record fields after any transfer to the caller boundary.
- Classify generated byte construction and concatenation acquisitions as generated-code leaf invocations. Classify enum naming, integer formatting, text concatenation, and quoting acquisitions as runtime-service-owned invocations. The caller must not acquire those service results a second time.
- Reserve three 16-byte frame cells for the 40-byte allocator request only in functions with generated-code invocations. The request begins immediately after the verified projected frame. Reject any successor projection above the retained 2,048-cell bound.
- Require every generated allocator invocation to preserve both `R11` instruction budget and `R10` call-depth budget around the WVA leaf. Runtime services remain responsible for their own native-call preservation boundary.
- Keep borrowing, call borrowing, caller acceptance, and callee transfer as ownership movement without allocator calls. The complete emission count must equal acquire plus retain plus release and must remain within the ownership-plan limit.
- Do not change ABI-22 descriptors, context bytes, generated code, fragment identity, native execution, console containers, or Windvale OS inputs in this planning slice.

## Consequences

The future full-allocator selector no longer needs to infer token addresses, action timing, scratch placement, service ownership, or volatile-budget handling. It can consume one verified row stream and the exact WVA leaf. The smallest executable successor fixture should begin with generated byte acquisition, alias retain, last-use release, and deterministic address reuse before adding direct records or runtime services.

The 22 runtime-service acquisitions are now a visible full-allocator gate. Exact native self-reproduction already succeeds through Decision 0150's bounded ABI-22 policy, but it cannot safely mix current service allocation with generated reclaiming operations over the same capacity. Each allocating service must adopt the same state/leaf contract before the exact compiler or shared OS consumer advances to the full allocator.

This decision does not implement owner-token descriptor copies, emit allocator calls, publish context 8, advance beyond ABI 22, alter the completed native compiler reproduction, rebuild PE/ELF containers, change Windvale OS, or retire .NET.

## Reconsider when

- A selected call sequence cannot preserve `R10`/`R11` and the existing stack/call convention within the measured frame bound.
- An allocating runtime service needs a state boundary that cannot use the append-only context pointers.
- Recoverable traps, concurrency, cyclic ownership, or nested records require phases or addressing modes not represented here.
- Independent instruction reconstruction proves that a different request placement materially simplifies or strengthens the successor ABI.

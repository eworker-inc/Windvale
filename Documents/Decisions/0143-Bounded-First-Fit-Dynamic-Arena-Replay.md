# Decision 0143: Bounded first-fit dynamic-arena replay

- Date: 2026-08-03
- Status: Implemented with local Windows evidence; cross-host qualification pending
- Retains: Native ABI 21, execution-context version 7, target `x86-64-wvb-baseline-v21`, the 16 MiB dynamic-value capacity, and immutable `text`/`bytes` semantics
- Refines: [Decision 0137](0137-Bounded-Owned-Values-Before-Dynamic-Collections.md) and [Decision 0141](0141-Exact-Compiler-Dynamic-Value-Lifetime.md)

## Context

Decision 0141 proves an ideal 9,030,829-byte live and allocation-operation peak across 17 dynamic backings. That is not enough to select an allocator: alignment, per-block ownership metadata, address placement, split spans, fragmentation, and delayed input release may make a fixed region fail even when the sum of useful bytes fits.

The next evidence must use one concrete bounded policy. It must preserve immutable operation inputs until their result has been placed, fail rather than expand beyond the retained capacity, recover after success and failure, and remain general runtime machinery rather than a compiler-specific exception.

## Decision

- Add an opt-in first-fit allocator replay to the Stage 0 reference-runtime lifetime tracker. `Collectˉdynamicˉallocatorˉtrace` implies backing-identity tracking but does not change default reference execution.
- Model exactly one fixed arena. The production-evidence CLI uses the retained 16,777,216-byte capacity; focused tests may select a smaller positive 16-byte-aligned capacity.
- Charge every backing a 16-byte in-band header and round the complete header-plus-payload block upward to 16-byte alignment. Zero-length payloads still require one 16-byte block.
- Keep free spans in address order. Allocation chooses the first span large enough, consumes its low-address prefix, and leaves any exact remainder. Release inserts the span and immediately coalesces adjacent predecessor and successor spans.
- Preserve current allocating-operation inputs until the new block has been placed. Backings that lose their last typed root are pending releases; older pending releases are reclaimed before the next allocation, while backings named by that allocation's inputs remain occupied through placement.
- Cancel a pending release if an internal call return, local transfer, record field, or other typed root revives the backing before reclamation. Reviving an already released backing is an invariant failure.
- Use checked arithmetic for payload charge, block boundaries, arena totals, peak metrics, and counters. An unplaceable block records the first failed request and largest free span, then traps as diagnostic `WVR3018`; the fixed arena never grows.
- Require reset to observe zero allocated blocks and one completely coalesced full-arena span. Successful and failed focused runs both end with zero retained blocks and charged bytes.
- Add `--report-dynamic-allocator`. Its deterministic report includes allocation/reuse counts, peak payload and charged storage, peak block count, maximum addressed extent, peak external fragmentation, maximum free-span count, first failure evidence, and retained state.
- Keep the simulator out of ordinary execution and the multi-billion-instruction replay out of normal verification. Windows and Linux CLI gates use the bounded Foundation fixture, while a small runtime case proves exact coalescing and exhaustion behavior.
- Do not change ABI 21 from simulator evidence alone. The next native slice must publish a descriptor-ownership and retain/release plan before generated bytes, context layout, or service tables change.

## Local evidence

The canonical 12-module Stage 1 compiler succeeds under the concrete 16 MiB policy after exactly 6,700,562,174 verified instructions. It returns zero, emits the established valid-source report, and produces the byte-identical 599,868-byte Stage 2 compiler with SHA-256 `9673bf3331763181f443ec67b7a513bc66daa718969f7f6b0d197a4186071066`.

The trace performs 1,852,773 successful allocations and reuses an already addressed region for 1,852,722 of them, approximately 99.99725%. Peak payload remains 9,030,829 bytes across 17 blocks; headers and alignment raise the charged peak by only 387 bytes to 9,031,216. That leaves 7,746,000 bytes inside the fixed arena at the charged peak.

First-fit placement reaches a maximum addressed extent of 10,700,368 bytes, leaving 6,076,848 bytes, approximately 5.80 MiB, above that extent. External fragmentation peaks at 7,324,224 bytes and the trace reaches 86 simultaneous free spans, but no request fails. Completion recovers zero retained blocks/bytes and one full coalesced arena. The local Windows Release replay completes in 622.891 seconds.

The Foundation byte-construction CLI fixture performs 35 allocations, reuses 12 placements, and turns 6,291,475 peak payload bytes into 6,291,600 charged bytes across five blocks. It reaches address 8,389,040, peaks at 4,194,640 bytes of external fragmentation and three free spans, fails no allocation, and retains nothing.

The focused policy fixture uses an arena of exactly 64 bytes. A helper frame owns two adjacent 32-byte charged results, returns a scalar, releases both blocks, coalesces the complete region, and then admits one 64-byte quoted-text result. The same program under 48 bytes admits the first 32-byte block, rejects the next against a 16-byte largest span as `WVR3018`, and still recovers to zero retained storage. A 63-byte misaligned arena is rejected before execution.

The focused construction, lifetime, coalescing, exhaustion, reset, and CLI cases pass after a zero-warning build. No WVB/WVO bytes, source semantics, native ABI, machine fragment, OS source, or guest artifact changes in this diagnostic slice. QEMU is not rerun because no OS input changes.

Change-aware Windows verification selects the qualification-scale compiler/runtime path, completes a zero-warning Release build, and passes all 81 selected Seed tests in 350.412 suite seconds. The 246.518-second golden compiler contract and the new four-millisecond allocator/coalescing case both pass. This development gate is proportional local evidence, not cross-host qualification.

## Consequences

The existing 16 MiB capacity is sufficient for an ordinary, implementable first-fit/coalescing policy over the exact compiler, including explicit header/alignment charges and real fragmentation. A larger arena, rope representation, tracing collector, or compiler-name special case is not the first repair.

Actual native ownership still needs a verifiable identity. The existing 16-byte descriptor already has an unused `u32` reserved word: a future ABI candidate can use zero for borrowed values and a nonzero arena-relative owner token for allocated backings. Slices can preserve that token while changing their data pointer and length. A 16-byte block header can then carry bounded physical-link, payload, state, and reference information without widening every descriptor. This representation remains a planning input, not implemented ABI behavior.

The next slice must preserve descriptor ownership in native machine IR and derive deterministic retain, release, transfer, frame-cleanup, direct-record-field, call-argument, and caller-owned-return actions. An independent verifier must reconstruct that plan before allocator leaves or generated ownership instructions are admitted. Only then should a successor ABI replace the monotonic cursor.

This decision does not implement native reclamation, select permanent collection semantics, add dynamic collection syntax, advance WVB 1.7 into native execution, qualify native compiler self-reproduction, retire .NET, or advance the OS guest ABI.

## Reconsider when

- The ownership plan cannot cover slices, aliases, direct-record fields, calls, returns, capability borrows, and failure cleanup without widening the descriptor.
- Native metadata or independently decoded allocator mechanics exceed the measured headroom.
- Another real workload fails first-fit despite remaining total free space, or makes bounded scan/coalescing costs unacceptable.
- Cyclic values, concurrency, globals, closures, or long-lived resources require a mechanism beyond acyclic retain/release ownership.

# Decision 0354: Native compiler-image staging reconstruction

- Status: Accepted current-host reconstruction evidence; native host-container construction, Linux execution, and grouped qualification pending
- Date: 2026-08-07
- Advances: [Decision 0353](0353-Native-Compiler-Image-Staging-Source-Build.md), [Decision 0346](0346-Bounded-Native-Publisher-Self-Lowering.md), and [Decision 0057](0057-Windvale-Native-Execution-And-Dotnet-Retirement.md)
- Contract: [Windvale linking](../../Specifications/Windvale-Linking.md#hosted-immutable-snapshot-staging-boundary)

## Context

Decision 0353 removed Stage 0 from source-to-WVB construction for the
compiler-image staging tool. The application test still handed that WVB to the
C# backend and used its `Nativeˉfragment` directly when constructing the host
containers. Before replacing the service bundle and PE/ELF constructors, the
repository needed evidence that the existing Windvale-native segmented
producer and staging linker could reconstruct the same native object and flat
image from the natively built WVB.

The ordinary whole-object native lowerer is not the correct large-tool route.
A direct probe accepted the exact 75,337-byte WVB input but exited with status
1 without publishing a WVO or diagnostic. The segmented producer already owns
bounded function batches, `WVOP` publication, and compiler-scale output without
one complete generated byte value.

## Decision

- Build the compiler-image staging WVB through the ordinary native Project 1
  front door and require its existing pinned identity.
- Run that exact WVB through the current-host digest-bound segmented WVO
  producer. Admit at most 62 nonempty chunks so the downstream immutable
  snapshot table remains sufficient.
- Reconstruct the complete staged WVO only in the managed evidence harness and
  compare every byte with the independently built Stage 0 recovery oracle.
  Independently parse and verify the reconstructed object.
- Pass the unchanged `WVOP` and chunks to the current-host compiler-image
  staging application. Reconstruct the resulting `WVLI` sequence only in the
  evidence harness and compare every linked byte and the exact `Main` entry
  with the Stage 0 linker oracle.
- Bound the evidence reader before allocation: one through 62 chunks, at most
  4 MiB per chunk, and at most 32 MiB in aggregate. Require indices, positions,
  lengths, manifest size, and complete coverage.
- Require both native child processes to load no CLR, hostfxr, hostpolicy, or
  dotnet component.
- Keep C# limited to temporary application construction, orchestration, and
  independent differential evidence. This decision does not call the host
  containers natively constructed or add an ordinary promoted launcher.

## Evidence and consequences

After reviewing the focused test, the affected Seed test project builds with
zero warnings in 19.59 seconds. The exact named case passes 1/1 in 12.184 test
seconds. The native source front door again publishes the 75,337-byte WVB at
SHA-256
`855983284c088cd795c119fe0c392308824066b10a9173dceb7cdc2daa219101`.

The current-host segmented producer emits a strict bounded `WVOP`; joining its
declared chunks reproduces the complete Stage 0 WVO byte for byte. The
compiler-image staging process then acquires that manifest and every chunk as
immutable snapshots, independently verifies each produced image value, and
emits a strict `WVLI`; joining those values reproduces the complete Stage 0
flat image and entry. Neither child loads a managed runtime component.

The numbers checked during this test come from two sources with different
roles: the WVB length and digest are frozen contract values, while the complete
WVO, image, and entry are recomputed by the independent Stage 0 recovery
oracle and compared byte for byte with the native processes. This is still
differential evidence, not a permanent post-Stage-0 fixture.

Stage 0 still constructs the segmented-producer and compiler-image-staging
PE/ELF applications and supplies the temporary differential oracle. Native
service-bundle construction, host-container reconstruction, a digest-bound
ordinary composition launcher, durable public image publication, canonical
map output, Linux execution, promotion, Development, Standard, Qualification,
and the grouped retirement gate remain open. No broader local test level was
run.

## Reconsideration triggers

Freeze a versioned post-Stage-0 WVO/image fixture before deleting the
differential oracle. Revisit this composition if the staged producer, `WVOP`,
segmented linker, `WVLI`, compiler-image profile, native ABI, service bundle,
or host-container formats change. Do not replace the segmented path by
widening the ordinary whole-value arena.

# Decision 0121: WebAssembly calls with structured control

- Date: 2026-08-02
- Status: Implemented with local Windows, Node.js, and Chromium evidence; cross-host and cross-browser qualification pending
- Numbering note: This historical record shares number 0121 with [Deterministic WVA scalar and memory operands](0121-Deterministic-Wva-Scalar-And-Memory-Operands.md); references must use the complete title and filename.
- Extends: [Decision 0120](0120-Bounded-WebAssembly-Call-Graph.md)
- Target: `wasm32-browser-v1-experimental`

## Context

Profile 5 independently qualified sequential loops and conditionals in one function. Profile 6 independently qualified a bounded acyclic direct-call graph with one shared execution budget. Ordinary programs need both at once: helpers called from loops and conditional routes, with the same checked arithmetic, resource accounting, and status propagation as straight-line callers.

The two prior profiles already share the same scalar semantics and ABI 2. Their remaining composition risk is structural: a selector must reconstruct branch regions while traversing real call instructions, preserve WVB local types including compiler-produced `bool` temporaries, and ensure no call or edge weakens the static call-depth or nonnested-control bounds.

## Decision

- Add experimental profile 7 for profile-6 multi-function modules containing at least one real direct call and at least one profile-5 `while`, `if`, or `if/else` region.
- Admit compiler-produced `bool` locals in addition to `i32` locals. Check their WVB types before representing both families as target `i32` locals.
- Permit calls before, after, and inside sequential nonnested control regions. Retain decreasing target ordinals, exact call arity, at most eight functions, and maximum dynamic Windvale call depth eight.
- Reconstruct every comparison, jump boundary, loop back edge, false edge, else join, call signature, and call target before emission. Reject malformed, crossing, overlapping, or nested regions and every forward, self, cyclic, or arity-invalid call without output.
- Emit control with WebAssembly `block`, `loop`, `if`, and `else`, and emit calls as real direct `call` instructions. Retain one shared ABI-2 counter, limit, and status across every generated function.
- Advance the .NET-free static page to the retained three-function loop-and-conditional artifact. Require exact `0/42/196` success and `3011/0/195` exhaustion evidence.

## Consequences

The direct backend now covers the useful composition boundary that previously separated profiles 5 and 6. Calls can execute dynamically inside loops and either conditional route without resetting instruction accounting. `WVR3007` and `WVR3011` still propagate as Windvale statuses rather than WebAssembly engine traps.

The profile remains deliberately bounded. Control regions cannot nest or overlap, calls must target lower canonical ordinals, functions return only `i32`, parameters are `i32`, and linear memory and richer value families remain absent. The Stage 0 compiler, mandatory general WVB verifier, and hosted execution of the Windvale lowerer are still required to produce the artifact.

## Local evidence

The retained true-route source defines `Add(i32, i32)`, looping `Build(i32)`, and exported `Main()`. Calls occur in the loop body and selected `if` body. It compiles to 716-byte WVB SHA-256 `cf519c2d636d6e7b22b54afacf632bf5e514982e030d5c8b799a5585e7f39120`. The selector emits a deterministic 2,729-byte import-free Wasm module with SHA-256 `3be50be3c2436638973eb68743f9fdd2e00df9816e50e498b432ff36468c3a77`. The reference runtime and Node.js agree on `0/42/196` and `3011/0/195`.

The matching false-route source calls `Add` from its `else` body. Its 722-byte WVB SHA-256 is `77e65ba692c8abc87dbac4dfeba174f3afc9191ac784b47a65becae8f0df2752`; its 2,729-byte Wasm SHA-256 is `35d75c30ef03dbb693a976cfaa31405ce90ecca4d393c5e93de8953fcf4658da`. Both runtimes agree on `0/42/153` and `3011/0/152`.

The independent C# decoder reconstructs generated types, wrapper and private bodies, meters, checked scalar operations, comparisons, blocks, loops, conditionals, else joins, calls, post-call status branches, and returns directly from verified WVB. A branch target outside its function and a nested call/control program fail as `Unsupportedˉcode` without output. All retained profile-1 through profile-6 generated bytes remain identical.

`Tools/Verify/Verify-WebAssembly.ps1` builds and executes fifteen retained artifacts under Node.js. The standalone verifier reconstructs and runs the embedded profile-7 artifact without loading a .NET asset. A fresh Chromium-based in-app browser reports the exact embedded SHA-256, `0/42/196`, `3011/0/195`, no console warning or error, and zero `.NET`, Blazor, or `_framework` URL among nine observed development assets. This is one browser-engine family rather than cross-browser qualification; cross-host qualification also remains pending.

## Rejected alternatives

Inlining calls inside regions was rejected because it would erase the real call boundary and avoid proving shared budget and status propagation.

Admitting nested control at the same time was rejected because it changes the region reconstruction model independently of call composition.

Treating `bool` locals as untyped target integers at selection was rejected because the backend consumes untrusted serialized WVB and must preserve source stack and local type rules before lowering.

## Reconsider when

- Nested structured regions are required by representative programs and can be independently reconstructed.
- A versioned linear-memory ABI can carry text and byte buffers without leaking host conventions into Windvale semantics.
- A dynamic call-depth counter can admit recursion or less restrictive call ordering.
- A Windvale-native verifier or browser compiler can replace another Stage 0 artifact-production component.

# Decision 0538: First native capability-provider call emission

- Date: 2026-08-13
- Status: Implemented candidate with focused Windows execution and Linux image evidence
- Requires: [Decision 0537](0537-Bounded-Native-Capability-Provider-Table.md)
- Advances: [first pre-opened random-access storage](0212-First-Preopened-Random-Access-Storage.md) and the [Windvale Database proposal](../Project/Windvale-Database-Proposal.md)
- Defines: [first native capability-provider call](../../Specifications/Windvale-Native-Provider-Call.md)
- Retains: Native ABI 22, execution-context version 7, service-table version 5, WVB 1.11, WVO 1.0, and every accepted hosted container
- Plans: Native ABI 23 with append-only execution-context version 9

## Context

Decision 0537 supplies a bounded immutable table with one target and
rights-limited state address per WVB capability ordinal. It intentionally stops
before choosing generated x86-64 bytes. The storage capability has five typed
parameters, while ABI 22 supports only its six fixed capability shapes and has
no generic stateful dispatch.

Decision 0151 already reserves context offsets 112 and 120 for allocator state
and its leaf. Reusing either for database dispatch would make two incompatible
plans appear layout-compatible. A provider call also needs an exact argument
shape that preserves the generated instruction and call-depth budgets and can
be reconstructed independently before executable publication.

## Decision

- Reserve context offset 128 for the `WVPT 1` pointer in candidate context
  version 9, size 136. Retain the allocator reservations at offsets 112 and 120.
- Emit one fixed 216-byte sequence for the first five-cell provider shape.
  Select the entry by verified WVB ordinal; perform no runtime name lookup.
- Copy all five complete 16-byte value cells to an 80-byte outgoing area. This
  preserves scalar zeros and the complete borrowed-bytes descriptor without
  exposing the caller frame to provider mutation.
- Pass provider state in `R8`, the cell array in `R9`, the caller-owned result
  cell in `RCX`, and exact cell count five in `EDX`; call the entry target through
  `RAX`.
- Require every provider leaf to preserve `R10`, `R11`, and `R15`. Restore the
  outgoing area before testing provider status and use the existing generated
  service-failure branch for nonzero `EAX`.
- Limit ordinals to 32 and physical slots to the retained 2,048-cell frame
  envelope. Invalid emission input returns the original byte string unchanged.
- Implement a separate structural verifier that checks every selected byte,
  displacement, source/destination cell, result slot, count, call, restoration,
  and relative failure target.
- Do not modify the ABI-22 main lowerer or claim executable provider dispatch in
  this decision. Integration requires context 9, fragment verification, and a
  real provider target in the same coherent publication boundary.

## Evidence

The emitter and verifier compile separately through the native source front
door. Their focused Project 2 test builds deterministically to a 20,798-byte WVB
at SHA-256
`f666fbdb0217b8eacf8ec57719feede8df1d2e2a949820ec79357f7eb0b840a2`.
It lowers to a verified 194,819-byte ABI-22 test object at SHA-256
`41f580aff278d1e34e0def0cd80974a1dd92269833ffdfb6dd38e68a54f3b9a6`.
The 211,968-byte Windows package executes with result zero, and the same native
fragment packages as a 212,992-byte Linux application.

The test verifies repeated byte identity, maximum ordinal and frame slots,
failure without output mutation, truncation, and mutations in the context load,
target displacement, cell-copy displacement, and return sequence. The emitted
216-byte sequence is data interpreted by the independent verifier; the test
does not execute that sequence as an ABI-22 capability call.

## Consequences

- The successor storage path now has exact generated bytes and an admission
  algorithm, not only a table or prose calling convention.
- The main lowerer can integrate one bounded component rather than growing
  another capability-specific service-table slot.
- Networking and other stateful providers can reuse the ordinal/state boundary;
  additional argument shapes still require explicit contracts and verification.
- Context 9 construction, ABI-23 object identity, fragment-verifier integration,
  random-access provider leaves, and real-file recovery remain open.

## Reconsideration triggers

Revisit this decision if platform execution proves that a copied cell cannot
retain required descriptor provenance, a provider needs more than five cells
before typed capability values exist, context 9 cannot coexist with allocator
integration, or independent decoding finds an unbounded or ambiguous machine
sequence.

# Decision 0063: Shared-budget native calls and static data

- Date: 2026-07-31
- Status: Cross-host qualified on Windows x64 and Debian x64
- Refines: [Decision 0062](0062-Dynamic-Native-Instruction-Budgets-And-Backward-Control-Flow.md)'s single-function budget boundary

## Context

Decision 0062 admits bounded native loops but deliberately retains one `Main() -> i32` function and no static data. Useful Windvale tools require internal function calls, recursion containment, and immutable module data without resetting resource counters, trusting host stacks, or creating separate JIT and AOT backends. The extension must keep identical generated bytes under Windows and System V x86-64, preserve exact interpreter instruction accounting across a complete call graph, and reject malformed call/data encodings before object or executable-memory publication.

## Decision

- Advance the internal experimental target to `x86-64-wvb-baseline-v5` and ABI version `5`. There is no compatibility reader for version 4; Decision 0062's exact evidence remains historical at its qualified commit.
- Admit verified portable modules with one exported `Main() -> i32`, any bounded number of internal functions using `i32` or `bool` parameters and returns, and immutable `i32` array data. Capabilities, nominal values, text, bytes, mutable data, allocation, and runtime services remain outside this slice.
- Limit this baseline to four parameters. Internal calls pass them in `R8D`, `R9D`, `ECX`, and `EDX`, which are volatile under both supported host ABIs. Native-local function and data symbols use deterministic ASCII machine names; only `Main` is exported.
- Extend the host bridge to six unsigned machine arguments `(0, instruction budget, instruction budget, call-depth budget, 0, call-depth budget)`. This places the instruction maximum in `RDX` and call-depth maximum in `R9` under both Windows and System V x86-64. `Main` copies them to reserved `R11` and `R10` before ordinary parameter registers can be reused.
- Keep one instruction counter and one call-depth counter across the complete call graph. Every function entry decrements `R10`; every normal, local-trap, and propagated-trap exit restores it. Underflow returns packed status 3 as recoverable `WVR3004`. Calls preserve `R10` and `R11`, inspect the callee's packed status, propagate failure without executing later WVB instructions, and store the successful low `EAX` result.
- Lower immutable `i32` array length to its verified constant and lower indexed reads through an unsigned bounds comparison. Negative and upper-bound failures both return packed status 4 as `WVR3005`.
- Append aligned immutable bytes to the in-memory fragment and encode only verified RIP-relative patches to their exact symbols. The WVO sink separates those bytes into `.rodata`, replaces the already resolved displacement with a canonical zero relocation field, and emits one ordinary relative relocation. Linking that object must reproduce the exact in-memory fragment.
- Independently decode every function prologue, shared counter, initialized frame slot, canonical parameter move, WVB charge/semantic group, call, data access, branch, return, trap epilogue, patch target, symbol range, and reachable byte before WVO or W^X publication. Every call argument count must agree with its decoded callee.

## Initial evidence

The focused Windows differential case passes with a zero-warning Release build. It covers zero- through four-parameter calls, Boolean returns, nested and noncommutative calls, local preservation, recursive success and exact depth exhaustion, immutable data length/load, data passed through functions, data loops, bounds traps, WVO `.text`/`.rodata` separation, linked-image equality, and hostile patch rejection.

The primary data/call program loops over an immutable array, invokes a two-parameter `Add` function for every element, and returns `29` through the reference interpreter, W^X JIT fragment, and WVO-linked AOT image at the same exact instruction and call-depth boundaries.

## Consequences

The shared native subset now has a real multi-function ABI, bounded recursion, immutable data addressing, and relocatable read-only object data while retaining one JIT/AOT selector and one independently verified fragment contract. Instruction limits remain semantic WVB limits rather than per-function native counters.

The four-register parameter ceiling is an explicit baseline limitation, not a source-language limit. A later stack-argument or aggregate ABI may replace it through a new version and new qualification evidence. The flat JIT fragment currently maps its immutable tail with the executable image while WVO records a true `.rodata` section; a future loader may publish separate page permissions without changing portable semantics.

This remains part of the independent C# Stage 0 reference and recovery implementation. The already self-reproducing Windvale bytecode compiler does not yet own executable-memory publication, this native selector, or its verifier. Porting those components into Windvale follows qualified ABI coverage and the native-compiler entry gate; C# is not the intended normal post-retirement compiler.

This decision does not claim capabilities, hosted calls, mutable globals, text/bytes, aggregates, allocation or garbage collection, asynchronous cancellation, PE/ELF hosts, native compiler execution, Windvale-written runtime ownership, or .NET retirement.

## Reconsider when

- More than four scalar parameters or aggregate values are required by the first native Windvale tool.
- Separate code/read-only page publication materially changes the in-memory fragment contract.
- Runtime services require a stable service table, stack maps, allocation safe points, or asynchronous cancellation.
- The Windvale-written native compiler begins reproducing this machine-IR, selector, verifier, and object contract.

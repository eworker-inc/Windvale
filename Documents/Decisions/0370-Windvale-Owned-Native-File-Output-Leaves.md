# Decision 0370: Windvale-owned native file-output leaves

- Status: Accepted current-host normal-path C# emitter removal; Linux execution and grouped qualification pending
- Date: 2026-08-07
- Advances: [Decision 0369](0369-Windvale-Owned-Native-Output-Leaves.md) and [Decision 0057](0057-Windvale-Native-Execution-And-Dotnet-Retirement.md)
- Contract: [Windvale native execution context](../../Specifications/Windvale-Native-Execution-Context.md#runtime-private-file-output-table)

## Context

The exact Windows and Linux `file.write_bytes` leaves no longer require
platform callbacks, but their complete x86-64 instruction streams were still
constructed and patched by one 450-line C# source whenever a native service
bundle was assembled. Their machine bytes and capability contract were already
stable, so keeping live instruction emission in the normal managed runtime
duplicated implementation ownership without adding a semantic check.

The file-output leaves are larger than the console leaves because they validate
resource names and values, create or truncate a file, complete partial writes,
durably flush, close, and map platform errors. Those responsibilities remain
platform-specific, but their source construction can be owned by focused
portable Windvale modules and the existing service-code builder.

## Decision

- Add one shared Windvale module for file-output emission helpers and focused
  Windows and Linux modules for the established platform leaves. Keep entry
  validation and Windows open emission in named helpers so the source remains
  reviewable and every function fits the native backend's bounded frame.
- Add one small bridge that returns the Windows leaf followed by the Linux
  leaf. Retain its exact WVB for source reconstruction, differential execution,
  qualification, and Stage 0 recovery.
- Require the ordinary native source-project front door to reproduce that
  bridge exactly.
- Embed only the two generated `.bin` leaves in `Runtime/Windvale.Native`.
  The normal runtime selects and verifies the exact platform leaf; it neither
  embeds nor executes the generator WVB.
- Remove C# instruction emission, label accumulation, relative-branch
  patching, and platform leaf construction. Preserve the runtime-private
  `WVFO` table, ABI registers, path and value limits, partial-write and durable
  flush behavior, contained failure details, service-bundle placement, and
  both leaf identities.

## Evidence and consequences

The affected test was reviewed before execution. Its focused contract compiles
and pins the builder, shared code, both platform cores, and bridge; compares the
retained bridge byte for byte; runs it through both the reference interpreter
and verified x86-64 backend; compares all 1,610 generated bytes with the two
embedded artifacts; proves the runtime does not embed the bridge; and
reconstructs the bridge through the ordinary native source front door.

The final focused Fast selection passes 1/1 in 2.390 seconds after a Release
build that succeeds with zero warnings and errors in 14.08 seconds. Both
qualification scripts pin the source, bridge, and leaf identities; only their
syntax is checked in this slice. The broader real-file behavior test was not
rerun because its managed table owner and leaf bytes did not change. No
Development, Standard, Qualification, grouped cross-host, or real Linux gate
was run.

The managed source is reduced from 450 lines of emitter and patching logic to
a 90-line exact artifact selector and verifier. Remaining managed ownership
includes platform file-output-table binding, file-input leaf construction,
service-bundle assembly, executable-memory ownership, contexts, arenas, and
invocation.

## Reconsideration triggers

Change either leaf identity only through an explicit file-output adapter
contract and complete descendant qualification. Keep the bridge WVB until the
final digest-bound Stage 0 archive exists. Replace the managed selector only
when a native host owner enforces the same platform choice, exact identity,
authorization, table validation, and W^X publication boundary.

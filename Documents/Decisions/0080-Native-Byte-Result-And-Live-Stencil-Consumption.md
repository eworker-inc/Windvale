# Decision 0080: Native byte result and live stencil consumption

- Date: 2026-08-01
- Status: Accepted, implemented, and cross-host qualified
- Extends: [Decision 0079](0079-First-Windvale-Native-Stencil-Consumer.md)
- Preserves: Native ABI 14, execution-context version 6, service-table version 4, WVB 1.6, WVO 1.0, kernel bridge 9, firmware probe 16, and both final process-input leaf identities

## Context

Decision 0079 moves exact object validation and semantic patch application into portable Windvale, but its demo can return only an `i32` status through the native entry. The live runtime therefore still asks the C# stencil consumer to produce both argument-service leaves. Using a hosted file or process-input capability to return the generated bytes would be circular because these are the leaves that implement the process-input capabilities.

The internal ABI already supports hidden 16-byte result cells for descriptor-returning functions. The missing seam is confined to the exported entry and the host's ownership check. A second service table, callback, binary loader, or OS-specific thunk would duplicate existing machinery.

## Decision

- Admit capability-free portable `Main() -> bytes` in the reference runtime and x86-64 baseline backend while retaining `Main() -> i32` unchanged. Hosted byte entries remain outside this slice because argument and file borrows have different owners; unsupported programs fail native compilation rather than reaching a partial runtime path.
- Keep ABI 14. Scalar entry bytes and calling behavior do not change, and no descriptor-returning `Main` was previously admitted by the backend. The managed bridge supplies the result-cell pointer in both its first Windows argument and fourth System V argument, which place the same value in physical `RCX`; `RDX` continues to carry the duplicated execution-context pointer.
- Generated descriptor entries copy `RCX` into `RAX`, then use the already-qualified hidden-result convention. The independent fragment decoder requires that exact bridge instruction when and only when exported `Main` has a descriptor result, classifies the decoded entry result, and rejects executor/result-kind mismatches before publication. Older verifiers reject the new prologue shape rather than executing it ambiguously.
- Allocate one zeroed 16-byte result cell for the call. On successful status only, require reserved word zero, length at most the 4 MiB WVB byte-value limit, and a complete range inside either one exact immutable fragment-data symbol or the committed used prefix of the execution arena. Copy the bytes before the W^X image, context, result cell, and arenas are released. Reject every other pointer/length shape as `WVN4012`.
- Add `Compiler/Windvale/Native-Stencil-Bridge.wv`. It embeds the two exact production WVOs, invokes the Decision 0079 consumer, and returns the five-byte and 70-byte leaves as one 75-byte immutable value. Any impossible rejected retained input produces an empty result, which the runtime identity gate rejects.
- Retain the exact compiled bridge as `Runtime/Windvale.Native/Consumers/Native-Stencil-Bridge.wvb`. The runtime verifies its size and digest, verifies WVB, lowers and independently verifies native code, executes it once through W^X, verifies both resulting leaf digests, and caches only the accepted immutable 75-byte bundle. The service-table path performs a fixed 5/70 split and rechecks each leaf identity before publication.
- Keep `X64ˉnativeˉstencil` as the independent C# reference/recovery oracle and malformed-object test surface. It is no longer the live constructor for either process-input leaf.

## Why ABI 14 is retained

This change does not reinterpret a previously valid descriptor entry: the backend formerly rejected every `Main` return other than `i32`. It adds one verifier-recognized export shape using bridge argument positions that were reserved padding, leaves all already-qualified scalar code and context bytes unchanged, and is rejected by the previous exact decoder. Advancing the global ABI, kernel bridge, and firmware probe would rebuild an unchanged service-free OS consumer without improving compatibility or safety. A future change that alters an existing accepted entry, context field, service call, value representation, or guest bridge must still advance the applicable version.

## Consequences

- Windvale now owns the live validation and construction of both process-input service leaves.
- C# still owns WVB loading, native lowering, independent fragment verification, W^X allocation/publication, execution arenas, invocation, status mapping, and lifetime cleanup. This is a real ownership reduction, not native self-hosting or .NET retirement.
- The next measured transfer can address W^X publication/lifetime or another compiler/runtime construction seam without inventing a byte-return callback.
- No arbitrary pointer escape, general FFI result, mutable buffer, asynchronous lifetime, executable-object loader, capability widening, or Windvale OS runtime is introduced.
